# File_Manager

Консольный файловый менеджер с базой данных и защитой от типовых уязвимостей.
Семестровое задание №1 по дисциплине «Технологии разработки безопасного программного обеспечения».

- Язык: Python 3.14
- База данных: SQLite (модуль `sqlite3`)
- Интерфейс: консольный
- Сторонние пакеты: `psutil` (список дисков), `defusedxml` (безопасный разбор XML), `pytest` (тесты)

## Запуск

```
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

При первом запуске создаются каталоги `storage/` (файлы пользователей) и `data/` (база данных), оба с правами `0o700`.
Запускать нужно из обычного терминала: пароль вводится без отображения на экране.

Тесты:

```
python -m pytest -v
```

Тесты работают во временной папке и не трогают настоящую базу и `storage/`.

## Возможности

| Требование задания | Где реализовано |
|---|---|
| Список дисков и свойства файловой системы | `disks.py` |
| Чтение, запись, изменение и удаление файлов | `files.py` |
| Хранение и чтение JSON и XML | `formats.py` |
| Создание и распаковка ZIP с ограничениями | `archives.py` |
| Таблицы Users, Files, Operations | `db.py` |
| Аутентификация с хешированием паролей | `auth.py` |
| Журнал аудита | `audit.py` |
| Консольное меню | `menu.py` |

Каждый пользователь работает только в своей папке `storage/<id>/`. Файлы лежат в ней плоско, без подпапок.

## Структура проекта

```
main.py                 точка входа: каталоги, схема БД, меню
file_manager/
    config.py           пути, лимиты и шаблоны допустимых имён
    db.py               подключение к SQLite и схема таблиц
    auth.py             хеширование паролей, регистрация, вход, блокировка
    audit.py            журнал событий безопасности и история операций
    disks.py            список дисков
    files.py            безопасный путь, чтение, создание, изменение, удаление
    formats.py          JSON и XML
    archives.py         ZIP
    menu.py             консольное меню и безопасный вывод в терминал
tests/                  тесты pytest
```

Код разбит по модулям с одной ответственностью (SRP) вместо одного «божественного» класса.

## База данных

- `users` — id, username (уникальный), password_hash.
- `files` — id, filename, created_at, size, location, owner_id → users.
- `operations` — id, timestamp, operation_type (create / modify / delete), file_id → files, user_id → users, file_path.
- `audit_log` — id, timestamp, event_type, user_id → users, details.

Особенности:

- Все запросы с данными выполняются через подготовленные выражения с `?`. `executescript` используется только для создания схемы из текста в самом коде.
- Включена проверка внешних ключей (`PRAGMA foreign_keys = ON`), допустимые значения `operation_type` и `event_type` ограничены через `CHECK`.
- Запись в `files`, запись в `operations` и действие на диске выполняются в одной транзакции: если запись на диск не удалась, строки в БД откатываются.
- При удалении файла `operations.file_id` обнуляется (`ON DELETE SET NULL`), а история остаётся читаемой по столбцу `file_path`.
- Время хранится в UTC и переводится в местное при показе.

## Защита от уязвимостей

| Угроза | Защита |
|---|---|
| SQL-инъекции | Только параметризованные запросы; логин проверяется по белому списку символов |
| Command injection | Оболочка и внешние команды не вызываются вообще; диски читаются через `psutil` и `shutil` |
| Path traversal | `resolve_safe_path`: путь приводится к абсолютному и проверяется, что он остался внутри папки пользователя; имена файлов проверяются по белому списку |
| TOCTOU и симлинки | Файлы открываются через `os.open` с `O_NOFOLLOW`; создание — с `O_CREAT \| O_EXCL`; размер проверяется чтением `лимит + 1` байт, а не отдельным `stat` |
| Слабые хеши паролей | PBKDF2-HMAC-SHA256, 600 000 итераций, случайная соль 16 байт на каждый пароль |
| Timing-атаки и перечисление пользователей | `hmac.compare_digest`; для несуществующего логина проверяется фиктивный хеш; ответ «Неверный логин или пароль» одинаков |
| Подбор пароля | Блокировка на 15 минут после 5 неудачных попыток, считается по логину |
| DoS через хеш | Число итераций в сохранённом хеше ограничено сверху |
| XXE и billion laughs | Разбор XML только через `defusedxml` с `forbid_dtd=True` |
| Инъекция в XML при записи | Имена тегов и атрибутов проверяются по белому списку; результат перед сохранением разбирается заново |
| Глубокая вложенность JSON и XML | Лимит 50 уровней, обход дерева без рекурсии |
| Нестандартный JSON | `NaN`, `Infinity` и числа, не помещающиеся в `float`, отклоняются |
| ZipSlip | Имя каждой записи архива проверяется тем же белым списком, что и обычные имена файлов; папки в архиве запрещены |
| Zip-бомбы | Не более 100 файлов, 50 МБ суммарно, 10 МБ на файл, коэффициент сжатия не выше 100; реальный размер считается при чтении, а не берётся из заголовка |
| Переполнение диска и памяти | Размер файла ограничен 10 МБ при чтении и записи |
| Log injection | В журнал попадает либо логин, прошедший белый список, либо `repr` от ввода; длина записи ограничена |
| Управляющие последовательности терминала | Перед выводом на экран всё, кроме печатных символов, перевода строки и табуляции, заменяется на `?` |
| Утечка сведений в ошибках | Пользователь видит короткое сообщение без путей и текста исключения |

Журнал `audit_log` фиксирует регистрацию, успешный и неудачный вход, выход, отказ в доступе и превышение лимитов.
Если записать событие в журнал не удалось, вход не выполняется.

## Известные ограничения

Аутентификация:

- Блокировку можно использовать, чтобы на время закрыть вход чужому аккаунту.
- Между подсчётом неудачных попыток и записью новой есть гонка при одновременных входах.
- Если пользователь по ошибке ввёл пароль в поле логина и он похож на логин, он попадёт в журнал.
- Неудачные попытки входа по несуществующему логину пользователю не видны: роли администратора нет.
- Запись о выходе появляется только при выходе через меню, а не по Ctrl+C.

Файлы:

- `O_NOFOLLOW` защищает только последний компонент пути. Подмена самой папки пользователя симлинком не обнаруживается.
- Именованный канал (FIFO), оказавшийся в папке пользователя, подвесит чтение.
- Сбой посреди записи оставит обрезанный файл без строки в БД; сбой фиксации транзакции после записи — файл без строки в БД.
- Файл, положенный в папку пользователя в обход программы, можно прочитать, но он не виден в списке и его нельзя изменить или удалить.
- Из меню содержимое файла вводится одной строкой.

JSON и XML:

- Любой XML с `DOCTYPE` отклоняется, даже безобидный. XInclude не обрабатывается.
- Имена тегов и атрибутов при записи — только латиница, без пространств имён и комментариев.
- Повторяющиеся ключи в JSON схлопываются (остаётся последний), нестроковые ключи при записи становятся строками.
- Схема содержимого не проверяется.
- Из меню нельзя перезаписать существующий JSON или XML; XML создаётся только из корня и одного уровня вложенных элементов.

ZIP:

- Подпапки не поддерживаются ни при создании, ни при распаковке.
- Архивы с паролем и архивы больше 10 МБ отклоняются.
- Распаковка держит содержимое в памяти (до 50 МБ).
- Существующие файлы при распаковке не перезаписываются: при совпадении имён распаковка отменяется целиком.
- Отмена распаковки делается удалением уже созданных файлов, поэтому в истории остаются пары create и delete; при аварийном завершении посреди распаковки часть файлов останется.

Диски:

- Объём и свободное место — снимок на момент вызова. На macOS показывается один раздел `/`.

## Тесты

140 тестов в каталоге `tests/`:

- `test_auth.py` — хеширование и проверка паролей, правила для логина и пароля.
- `test_login.py` — регистрация, вход, блокировка, SQL-инъекция в логине, записи в журнале.
- `test_files.py` — операции с файлами, path traversal, симлинки, лимит размера, изоляция пользователей.
- `test_formats.py` — JSON и XML: XXE, billion laughs, DTD, вложенность, инъекция через имена тегов.
- `test_archives.py` — ZIP: ZipSlip, zip-бомба, лимиты, откат распаковки.
- `test_audit.py` — журнал, ограничения схемы БД, видимость только своих записей.
- `test_system.py` — диски, служебные каталоги, безопасный вывод в терминал.
